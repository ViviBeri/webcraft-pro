# Security Policy

Security is a core requirement of WebCraft Pro.

## Supported versions

Security fixes are prioritized for the latest version on the `main` branch and the latest stable release.

## Reporting a vulnerability

Please do not disclose exploitable vulnerabilities in public issues.

Use GitHub's private vulnerability reporting feature:

1. Open the WebCraft Pro repository.
2. Select the Security tab.
3. Select Advisories.
4. Choose Report a vulnerability, if available.

If private vulnerability reporting is unavailable, contact the repository maintainers privately through an appropriate GitHub contact channel.

## Include in your report

- Affected component or file.
- Vulnerability description.
- Reproduction steps.
- Potential impact.
- Suggested mitigation, if known.

Do not include real credentials, personal information or sensitive production data.

## Security engineering standards

Our security guidance should prioritize:

- OWASP Application Security Verification Standard.
- OWASP Cheat Sheet Series.
- Secure authentication and authorization.
- Input validation and output encoding.
- Secure session management.
- Dependency and supply-chain security.
- Least-privilege permissions.
- Secret management.
- Security testing and verification.

## Response

Maintainers will review reports, assess severity, investigate reproducibility and coordinate fixes and disclosure.

Please allow maintainers reasonable time to investigate before public disclosure.

## Scope

This policy covers security defects in WebCraft Pro source files, documentation, examples, automation and maintained tooling.

Third-party services and unrelated external projects are outside this repository's direct control.
