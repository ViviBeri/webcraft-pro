# v1.6.0 Scope Decision Log

Record decisions that change the frozen release contract. Keep deferred work visible without silently reintroducing it.

## 2026-11-20 — Freeze v1.6.0 around five verifiable deliverables

- **Decision:** Must ship selective installation, Skill Doctor, a tested agent compatibility matrix, QuickStart/contributor onboarding, and documentation consistency CI.
- **Rationale:** These improve core adoption and repository trust while remaining independently testable.
- **Rejected alternative:** Shipping a benchmark, three showcase applications, and a full playground in the same release would expand scope and require separate evidence.
- **Source:** [v1.6.0 scope](v1.6.0-scope.md).

## 2026-11-20 — Reuse existing installer and validator work

- **Decision:** Extend `scripts/install-skills.mjs` and share validation rules with the existing validator and routing corpus.
- **Rationale:** Replacing existing tools or creating parallel validation logic increases maintenance cost and risks inconsistent rules.
- **Source:** [Baseline review](v1.6.0-baseline-review.md), [Issue #11](https://github.com/ViviBeri/webcraft-pro/issues/11), and existing validation scripts.

## 2026-11-20 — Keep benchmark and multi-app showcase work out of v1.6.0

- **Decision:** Keep the current benchmark example labelled illustrative. Defer reproducible model benchmarking and three complete showcase applications to v1.7+.
- **Rationale:** A credible benchmark requires controlled prompts, model/version metadata, repeated runs, scoring criteria, raw outputs, and limitations. Complete showcase applications require implementation and verification evidence.
- **Source:** [v1.6.0 scope](v1.6.0-scope.md) and `examples/benchmark/README.md`.

## 2026-11-20 — Require invocation evidence for agent compatibility

- **Decision:** Mark an agent verified only after installation, discovery, representative skill invocation, and output validation.
- **Rationale:** A readable skill file does not demonstrate that an agent can discover, select, and apply it correctly.
- **Source:** [v1.6.0 scope](v1.6.0-scope.md).
