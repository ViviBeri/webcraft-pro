# WebCraft Pro v1.6.2 Release Checklist

## Release gate — carry-over items

**Definition.** A carry-over is any issue that satisfies at least one of:

- Originally targeted at v1.6.0 or v1.6.1, did not ship in that release, and
  remains open at the start of v1.6.2 work.
- Originally targeted at v1.6.0 or v1.6.1, did not ship in that release, was
  re-targeted at v1.6.2, and is now either open or was closed **after** its
  original release date.
- Was explicitly deferred in release notes, milestone comments, or issue
  comments referencing v1.6.0 or v1.6.1, regardless of current state.

Issues closed *before* their original release shipped are not carry-overs
and do not appear.

**Identification — primary queries.**

Enumerate all states in the current and both original milestones. The union
is intentional: it retains issues that were completed during v1.6.2 work
without being re-targeted to the v1.6.2 milestone.

```sh
gh issue list --state all --milestone v1.6.2 \
  --limit 1000 --json number,title,state,closedAt,stateReason,milestone

gh issue list --state all --milestone v1.6.0 \
  --limit 1000 --json number,title,state,closedAt,stateReason,milestone

gh issue list --state all --milestone v1.6.1 \
  --limit 1000 --json number,title,state,closedAt,stateReason,milestone
```

**Truncation check.** Apply the check independently to each query. If the
returned count equals `--limit`, re-run with `--limit 5000`; repeat with
a higher limit until the returned count is below the requested limit. If
the CLI/API refuses a larger limit or the result still reaches the limit,
use the paginated fallback and do not treat the truncated result as
complete. De-duplicate the union by issue number. Record each final count
here: v1.6.2 `____`; v1.6.1 `____`; v1.6.0 `____`; union
`____ issues`.

**Identification — fallback.** If a milestone does not exist or any primary
query cannot be proven complete, enumerate using both release cutoffs from
the npm registry (the repo does not carry v1.6.x tags):

```bash
V160_DATE=$(npm view webcraft-pro time --json | jq -r '."1.6.0"')
V161_DATE=$(npm view webcraft-pro time --json | jq -r '."1.6.1"')

gh api --paginate --slurp \
  'repos/{owner}/{repo}/issues?state=all&per_page=100' \
  > all-issues-pages.json

gh issue list --state all --limit 1000 \
  --search "\"deferred to v1.6.0\" OR \"deferred to v1.6.1\" OR \"deferred to v1.6.2\" in:body" \
  --json number,title,state,closedAt,stateReason,milestone

gh issue list --state all --limit 1000 \
  --search "\"deferred to v1.6.0\" OR \"deferred to v1.6.1\" OR \"deferred to v1.6.2\" in:comments" \
  --json number,title,state,closedAt,stateReason,milestone
```

The paginated all-issues inventory is the exhaustive candidate source; exclude
pull requests. For each issue, inspect its milestone timeline to establish
whether its original target was v1.6.0 or v1.6.1 and whether it was later
re-targeted to v1.6.2. Compare `closed_at` with the applicable npm publish
timestamp to exclude issues closed before their original release shipped.
Also reconcile the body/comment searches and release notes or milestone
discussion for explicit deferrals. De-duplicate by issue number. Record both
npm publish timestamps, enumeration date, every timeline/deferral source,
page count, filters, and final candidate count below.

No implicit carry-overs. Every candidate from the identification step must
appear above as closed, still-v1.6.2, or re-deferred with a linked reason.
A candidate missing from the table is an unexplained omission and blocks
release.

**Hard gate — Issue #12.**

Issue #12 is a hard gate for v1.6.2. The gate is satisfied only when both
of the following are true:

1. Every acceptance criterion recorded on #12 at the start of v1.6.2 work
   is met. Criteria are frozen once v1.6.2 work begins; any change requires
   a written justification linked in the v1.6.2 milestone and noted here.
2. #12 is closed with state reason `completed` — not `not_planned`,
   `duplicate`, or `wontfix`. Any other closure reason does not satisfy
   the gate.

If either condition is false, v1.6.2 does not ship.

#12 was missed in v1.6.1. v1.6.2 does not ship with #12 open, or with
#12 closed as not-planned. This is the only such gate and is not a template
for other issues.

- [ ] #12 acceptance criteria met (frozen at v1.6.2 start)
- [ ] #12 closed with state reason `completed`
