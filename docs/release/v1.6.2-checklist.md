# WebCraft Pro v1.6.2 Release Checklist

## Release gate — carry-over items

**Definition.** A carry-over is an issue whose original target was v1.6.0
or v1.6.1 but which did not ship in that release and either remains open,
was closed after that release, or was re-targeted at v1.6.2.

**Identification (reproducible — use the primary query; fall back only if
it returns incomplete results).**

Primary:

```sh
gh issue list --state all --milestone v1.6.2 --limit 1000 --json number,title,state
gh issue list --state all --search "milestone:v1.6.0 OR milestone:v1.6.1" --limit 1000
```

Fallback — if the milestone does not exist or the query returns incomplete
results, enumerate manually using this deterministic rule and record the
enumeration source (date, filter, issue links) below:

1. Record the v1.6.1 release date (`git log -1 --format=%cI v1.6.1`).
   Build the complete set of issues that were open on that date from both
   groups: issues still open now that were created on or before that date
   (`gh issue list --state open --limit 1000 --search "created:<=<DATE>"`), and issues
   closed after that date
   (`gh issue list --state all --limit 1000 --search "created:<=<DATE> closed:><DATE>"`).
2. Add every issue whose body or comments contain "deferred to v1.6.2"
   (`gh issue list --state all --limit 1000 --search "deferred to v1.6.2"`).
3. Reconcile the union of these candidate sets against the primary milestone
   queries. Inspect each candidate's issue body, timeline and comments for
   its original target release and whether it shipped. Record the issue
   number, source query, original target release, current status, and whether
   it qualifies as a carry-over per the definition above. Record zero-result
   sources explicitly. If any query reaches its 1,000-item limit, retrieve
   and reconcile all remaining pages with `gh api --paginate` before
   proceeding. Do not treat the manually maintained list as authoritative
   until every candidate from every source is accounted for.

**Reconciliation.**
For each identified carry-over:
- If closed, add its issue link and mark it closed.
- If still open, add a row below with a written re-deferral reason linked in
  the v1.6.2 milestone.

No implicit carry-overs. Every identified carry-over must appear below; do
not omit closed issues or open re-deferrals.
