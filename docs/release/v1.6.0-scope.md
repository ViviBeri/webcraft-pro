# WebCraft Pro v1.6.0 — Frozen Scope

**Status:** Proposed release contract  
**Target:** v1.6.0  
**Baseline:** [v1.6.0-baseline-review.md](v1.6.0-baseline-review.md)

## Release objective

Ship a smaller, verifiable release that improves installation, skill diagnostics, agent compatibility evidence, contributor onboarding, and documentation integrity. Do not expand scope to chase skill count, stars, or unverified marketing claims.

## Must ship

### 1. Selective skill installation

Extend the existing installer; preserve its safety behavior.

- `--stage` selects one or more valid lifecycle stages.
- `--skills` selects one or more canonical skill names.
- Preserve existing `--dry-run`; it must preview without writing.
- Preserve overwrite protection by default.
- Reject invalid stage/skill names with actionable errors.
- Keep full installation as the default when no selector is supplied.
- Report selected, installed, skipped, and rejected skills.
- Document safe cleanup/uninstall guidance without deleting unrelated files.

**Acceptance:** tests cover full, stage, skill, combined selection, dry-run, invalid names, existing destinations, and overwrite behavior. Existing installer tests pass. Update [Issue #11](https://github.com/ViviBeri/webcraft-pro/issues/11); do not duplicate it.

### 2. Skill Doctor

Add diagnostics on top of the existing validator. Share a rules module; do not create a parallel ruleset.

Checks:
- Frontmatter delimiters and supported YAML metadata.
- Required metadata, name/directory consistency, description constraints.
- Missing `SKILL.md` files and required repository files.
- Broken local skill/document references.
- Duplicate skill names and exact duplicate descriptions.
- Required skill sections and basic installation structure.
- Routing entries that reference missing skills.

Output:
- Human-readable diagnostics by default.
- Stable machine-readable output through `--json`.
- Each diagnostic includes file, rule ID, severity, explanation, and fix hint.

**Acceptance:** tests cover every implemented rule and malformed inputs. JSON is valid on success and failure with a documented schema. Do not claim semantic-overlap detection from simple string heuristics; similarity checks may be advisory only. Existing validator and routing tests continue to pass.

### 3. Agent compatibility matrix

Initial targets: OpenAI Codex, Claude Code, and GitHub Copilot.

For each agent, record tested version/date, installation path, discovery, representative skill invocation, output validation, limitations, evidence link, and status.

**Acceptance:** mark an agent verified only after installation, discovery, invocation, and output validation are tested. Untested agents remain `Not tested`. Reading a `SKILL.md` file is not proof of compatibility.

### 4. QuickStart and contributor onboarding

Improve the existing README, `CONTRIBUTING.md`, and QuickStart skill.

QuickStart must explain what WebCraft Pro is/is not, install skills, select and use one skill, verify the result, and find contribution guidance.

Contributor basics:
- Add issue templates for bugs and feature requests.
- Retain and refine the existing PR template.
- Document skill authoring, metadata, testing, and review expectations.
- Require honest limitations and verification evidence.

**Acceptance:** an unfamiliar developer can follow the documented clean-start path in five minutes or less under stated prerequisites. Templates request relevant evidence without irrelevant mandatory fields.

### 5. Documentation consistency CI

Add deterministic, network-independent checks for:
- Skill count and index agreement.
- Stage count and referenced stage directories.
- Local Markdown/HTML links and repository references.
- README, landing page, and canonical inventory agreement.
- `package.json` and `package-lock.json` version agreement.
- Routing corpus and skill references.

**Acceptance:** CI fails with actionable file/value diagnostics on internal-reference or count/version mismatches. External URL availability is not a required CI gate; keep it as a separate manual/scheduled check. Preserve least-privilege permissions and avoid secrets.

## Stretch — one adoption proof

Only if all five must-ship deliverables are complete, ship **one** of:
- One complete reference implementation with source, setup, relevant skills, and accessibility/security/performance evidence; or
- A static skill explorer that accurately presents the canonical skills and links to source.

This is non-blocking. Do not build both.

## Explicitly deferred to v1.7+

- Reproducible model benchmark and benchmark claims.
- Three complete showcase applications.
- Full interactive playground.
- Broad international outreach campaign.
- Expanded quality scorecard or single aggregate quality score.
- Full visual identity redesign.

The current benchmark example remains illustrative, not measured model performance.

## Release gates

- [ ] All five must-ship deliverables meet acceptance criteria.
- [ ] Full and selective installation pass in a clean target directory.
- [ ] Skill Doctor produces actionable human and JSON diagnostics.
- [ ] Compatibility claims link to actual test evidence.
- [ ] All 44 skills have been audited for failure-mode guidance; update existing Issue #12 from a file-by-file inventory.
- [ ] Documentation consistency CI passes.
- [ ] QuickStart and contributor path tested from a clean start.
- [ ] Security and accessibility workflows pass.
- [ ] README, website, compatibility docs, and release notes make evidence-backed claims only.
- [ ] Deferred work remains clearly labelled.

## Change control

Do not add features after this scope is accepted. A proposed addition must identify the user need or release-blocking defect, affected files/tests, overlap with existing work, and a decision-log entry in [v1.6.0-decisions.md](v1.6.0-decisions.md). Otherwise schedule it for v1.7+.
