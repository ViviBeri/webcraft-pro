# Stage 2 — Design Intelligence

## Purpose

Translate product context, user needs and brand constraints into a distinctive visual direction, coherent design system, intentional page journey and evidence-based interface critique.

## Canonical skills

- [Design direction](../../skills/design-direction/SKILL.md) — brief, art direction, visual calibration, tokens and the human confirmation gate.
- [Independent review](../../skills/independent-review/SKILL.md) — fresh-perspective critique for template feel, accessibility regressions and security edge cases before finalization.
- [Anti-slop UI](../../skills/anti-slop-ui/SKILL.md) — ordered redesign passes that preserve product truth.
- [Premium landing pages](../../skills/premium-landing-pages/SKILL.md) — visitor journey, information architecture and working conversion paths.
- [Visual design review](../../skills/visual-design-review/SKILL.md) — rendered evidence, severity and design scorecard.
- [Design system architecture](../../skills/design-system-architecture/SKILL.md) — semantic tokens, component foundations and governance.
- [Visual reference analysis](../../skills/visual-reference-analysis/SKILL.md) — extract principles from screenshots and references without copying.

## Reference research and attribution

- [unslop](https://github.com/heydamir/unslop) — audit first, establish product-specific direction, then refine the interface in deliberate passes. Its source is CC BY 4.0; WebCraft Pro uses independently authored guidance and does not copy its skill text.
- [taste-skill](https://github.com/Leonxlnx/taste-skill) — design judgment, adjustable composition/density/motion direction, specialized workflows and reference boards. The current upstream README describes v2 as experimental; WebCraft Pro does not adopt its hard constraints as universal rules.
- [scroll-craft](https://github.com/nateherkai/scroll-craft) — page journey, deliberate structural variety and screenshot-based verification. This is a motion/scroll reference, not a general design-system specification; see Stage 4 for motion implementation.

## Acceptance boundary

Stage 2 establishes design intent and review practice. It does not claim browser validation of a consuming website, WCAG conformance, conversion improvement or performance gains. Those require project-specific implementation and testing.
