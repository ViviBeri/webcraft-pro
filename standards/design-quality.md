# Design Quality Standard

This standard defines the shared quality bar for WebCraft Pro design and interface skills.

## 1. Product and audience fit

- Identify the product, audience, primary user task and business objective.
- Use verified product facts and supplied brand assets.
- Distinguish assumptions from confirmed requirements.
- Do not invent testimonials, customer logos, awards, metrics, certifications or product capabilities.

## 2. Visual hierarchy

- Make the primary message and next action easy to identify.
- Use typography, spacing, contrast and composition consistently.
- Ensure section order reflects the user's decision or task.
- Use repeated patterns intentionally rather than by default.
- Remove decorative effects that do not improve comprehension, identity, feedback or orientation.

## 3. Content quality

- Use specific, truthful headings and labels.
- Avoid generic filler and unsupported superlatives.
- Design for realistic content lengths, including errors and empty states.
- Ensure links and calls to action communicate their destination or result.

## 4. Responsive behavior

- Consider narrow mobile, tablet, laptop and wide desktop layouts.
- Reassess information priority on small screens; do not merely shrink desktop layouts.
- Prevent horizontal overflow, clipping and overlapping controls.
- Keep navigation, forms and primary actions usable with touch and keyboard input.

## 5. Accessibility

- Use semantic HTML and meaningful heading structure.
- Provide accessible names and labels for controls.
- Maintain visible keyboard focus.
- Check text and interface contrast.
- Provide appropriate alternative text for meaningful images.
- Respect reduced-motion preferences.
- Do not rely on color, animation or hover alone to communicate important information.

## 6. Motion and interaction

- Motion must support orientation, hierarchy or feedback.
- Keep essential content and controls available without animation.
- Avoid unnecessary scroll hijacking and motion that delays user tasks.
- Ensure interactive elements have clear hover, focus, active, disabled and error states where relevant.

## 7. Performance

- Optimize image dimensions, formats and loading.
- Avoid unnecessary JavaScript and dependencies.
- Reserve media dimensions to reduce layout shifts.
- Load fonts efficiently and use resilient fallback stacks.
- Measure performance rather than claiming it from code inspection.

## 8. Verification and reporting

- Inspect the rendered page when browser access is available.
- Record viewport sizes and test steps.
- Separate reproducible defects from subjective preferences.
- Report automated tool results only when the tools were actually run.
- State unverified areas and remaining limitations.

## Review outcome

A design is ready for handoff when it communicates the product clearly, supports its primary task, behaves responsively, preserves accessibility and has been checked against the relevant implementation requirements.

## 9. Evidence-based design review

Use the shared five-dimension scorecard when a structured review is useful:

| Dimension | Review question |
|---|---|
| Product specificity | Could this interface plausibly belong to a different product without changing its content? |
| Hierarchy and composition | Can users identify the main message, content order and next action? |
| Visual system | Are typography, spacing, color and surfaces coherent and reusable? |
| Responsive behavior | Does content reflow intentionally without clipping or losing priority? |
| Accessibility and interaction | Can people identify and operate controls across supported input modes? |

Score each dimension from 0 to 4: 0 = broken or harmful, 1 = major weakness, 2 = partial, 3 = effective, 4 = strong and evidenced. Record evidence for scores below 3. Mark untested dimensions as not assessed. Never average away a critical defect or treat the score as a compliance certificate.

## 10. Design decision record

For substantial redesigns, retain a short record of product and audience; user task and primary action; art-direction statement; reference observations and adaptations; token and component decisions; responsive and accessibility constraints; assumptions, risks and verification evidence.
